## What Exactly Is Git?
- The world's most popular version control system (VCS)
- Version control system - software that tracks and manages changes to files over time. 
    - Not exciting, but massively important for collaboration. 
- Allow users to revisit earlier changes, compare changes between versions, undo changes, and a whole lot more. 
- There are many version control options out there. 
- Tracks changes, compare versions, revert to a previous version, collaborate and share changes, combine changes. 
- Big picture - sets up checkpoints and allows us to go back to them. Kinda like a save point in a video game. 

## Realistic Example 
- Working on a website with others (each of these is a checkpoint):
    - Initialize project 
    - Work on a navbar
    - Add first row
    - Add more content
    - Finish bottom row
    - Change theme (forked away)
    - Update navbar (forked away)
- Imagine boss says they don't like the colors
    - Go back to the "finish bottom row" and start working from this point (forking)
    - Add third row
    - Add footer
    - Can then toggle between any of these things
    - Can also combine the checkpoints
        - "Add footer" and "Update navbar" would combine the two checkpoints

## Git vs. GitHub: What's the Difference?
- Git - version control software that runs locally on your machine. Don't need an account or internet. Can be used without ever touching GitHub.
- GitHub - service that hosts Git repositories in the cloud and makes it easier to collaborate with other people. You need to sign up for an account to use it. Online place to share work that is being done using Git. Takes what you make with Git on your computer and puts it online. 
    - We are going to start with Git then move onto GitHub.
